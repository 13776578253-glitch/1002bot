# M6 受控响应与迁移

受控响应允许操作者明确结束一个只读或模型等待中的 run。原必要回执和终态确认后，Runtime 按原 FIFO 处理下一项；原结果晚到时独立归档。不会自动取消普通新消息，也不会暂停/恢复旧执行栈。

## 装配与控制

```ts
const runtime = composeRuntime({
  world, provider, session, state,
  agent: new ConversationAgent({
    sessionId: 'session', operations: true,
    includeUnsuccessfulHistory: true,
  }),
  responsiveness: {},
  includeUnsuccessfulHistory: true,
  cleanupDeadlineMs: 1000,
});
```

`responsiveness` 不提供时保持既有装配，`runtime.responses` 为 undefined；提供空对象使用标准容量。`operations: true` 启用 Agent 的 `agent_operation_evidence`，需要同时启用 Runtime 响应性。它只查询证据，不拥有让出或修改任务的权限。启用响应性要求 Session.scan；MemorySessionStore 与 JSONL 均支持。

```ts
const control = runtime.responses!;
const target = control.snapshot().active;
if (target) {
  const receipt = control.yield(target);
  // requested 表示发出明确控制；仍通过 run_finished 观察结清。
}
```

目标是当时的 runId/generation。旧目标、正在结清、关闭受理、效果未确认的动作或让出名额已满均明确拒绝。安全让出不能替代原 cancel/stop：强制取消动作仍可能 unknown 并停止；安全让出可拒绝该动作，让它继续正常等待。

控制入口属于可信本地调用方。原 Console/TUI 的共享 RuntimeControl 没有扩展新控制命令；本批使用下面的独立离线操作入口。QQ 原文不解析为自动抢占或管理指令。

## 工具能力与原调用

World 工具可声明 `effects: 'none' | 'external'`。none 由可信实现保证不改变外部业务状态，缺省仍保守处理。Runtime 随本 run 固定声明与 owner；模型参数或工具名称不能改变分类。工具回执的 callId、名称和状态须匹配公共契约。

启用响应性时，World 获得 `context.origin`，包含原 Session/run/触发及 callId，仍通过 signal/generation 协作。该对象不提供 Session 写权限。调用 Promise 结算前须收回本次调用独占的本地等待资源；World 的共享连接另归生命周期。资源退出不证明远端业务动作已撤回，Provider 本地取消也不证明远端生成/计费停止。

被中断的已开始只读调用保存 cancelled 回执及 `output.operation` 原引用。允许失败/取消完整历史的 Agent 可用它明确查询；这只交付身份，不交付晚到观察。未开始的调用仍是 not_executed；已取得匹配回执保持真实结果。

## 独立记录与证据

| 事实 | 含义 |
| --- | --- |
| operation_detached | 普通交付权结束，原注册调用仍归 Runtime；先确认此记录再收束原 run |
| 普通 cancelled / run_finished | 逻辑执行结清，不声称本地原调用已退出 |
| operation_late returned | 取得匹配工具回执，实际 succeeded/failed/cancelled/unknown 在 result.outcome.status 中 |
| operation_late failed | 原注册 Promise 拒绝；有界原因保留 |
| operation_late discarded | Provider 旧响应未执行，或观察超限/无法序列化等原因，原身份仍保留 |

独立记录使用 schema=1 和 origin，不携带顶层 run/generation/来源或 delivery 权限。它们可在原终态前后出现，但不重开旧 run、不重新结清来源、不改写任务效果概要，也不自动进入普通历史。

```ts
const evidence = await runtime.responses!.readLate({ runId, callId, bytes: 32768 });
```

无已确认证据返回 undefined；查询超过预算拒绝整条。Agent 工具同样接受 runId/callId/可选 bytes，尚无结果返回 `{ found: false }`。明确查询的工具输出属于查询 run，之后可按原完整组策略成为正常历史；不是独立迟到记录自动混入其他 run。

`snapshot().operations` 显示原身份、detached 和 state：running 是普通等待，detached 是已撤权仍等待，confirming 是原 Promise 已退出且归档待确认。confirming 仍占登记位。World 未声明能力的未知动作结果只等待本地资源退出，不保存为可修正 unknown 的迟到观察。

## 容量与停止

| 参数 | 标准值 | 到达边界 |
| --- | --- | --- |
| pendingOperations | 3 个 Provider/World 在途或待确认条目 | 新调用在实际发起前拒绝 |
| yieldedOperations | 2 个主动让出后未退出调用 | 拒绝继续主动让出；强制停止仍受总条目上限 |
| lateRecordBytes | 32 KiB 完整 JSON 对象 | 观察超限保留 discard 原因；必要元数据超限按存储故障停止 |
| latePendingBytes | 128 KiB 待确认独立记录合计 | 必要追加超限停止，不静默丢失 |
| evidenceBytes | 32 KiB 完整 JSON 记录 | 显式查询整条拒绝，模型请求另受实际序列化预算 |

独立记录预算计量 UTF-8 JSON 对象，不含 Session 实现追加的行终止符；Session 自身的单条/累计容量继续适用。数值不是堆、token、远端服务并发或全体内部存储 I/O 的上限。`yieldedOperations` 必须小于总上限；记录预算不得超过待确认字节上限。

清理期限为正整数毫秒。M6 stop 撤权并等待通道、World 清理、原调用与必要记录；本地资源未退出时明确拒绝完成，状态保持 stopping，start 拒绝。资源后来退出且归档确认后可再次 stop 结清。重复 stop 共用原清理等待；不以 TTL 删除登记。已进入且永不返回的必要 Session 写入仍须等待，资源期限不能伪造确认。

内存存储不提供新进程恢复；JSONL 也不提供 fsync、自动动作重放或 unknown 解除。归档中缺少原撤权结算、出现重复/错配或 unknown 时，预检阻断，不自动补写事实。

inspectSession/diagnose 的 ready 只表示当前档案可审计，不证明正在运行的资源已经清理。停止失败的 AggregateError.errors 提供具体清理原因；同时查看 Runtime.status 和操作快照，不能以 ready 绕过 stopping。

## 离线操作与验收

```powershell
pnpm sample:m6
pnpm dev:m6
```

样例使用临时目录内真实 World/Session 文件和脚本模型，不连接服务。交互可依次输入：

```text
input observe A
wait A
input current
push 7
yield
finish input-1
finish input-2
ops
release A
settle
diagnose
stop
start
input resumed
finish input-3
quit
```

ops 在 release 前显示原调用仍被登记；release/settle 后 diagnose 应为 ready。`late RUN CALL` 查询控制/终态输出中的原 runId 和 call-1；`input evidence RUN` 则通过模型显式证据工具查询。wait/finish/settle 有有限本地等待，超时显示仍待完成；EOF 与 quit 清理样例自有调用。

文件保留用于审查，路径由启动输出给出。这里的测试 World 只展示同实体/epoch 版本比较，迟到旧观察不覆盖新快照；没有交付通用 Observation 缓存或生产 QQ 响应性。

## 读取端迁移

普通旧日志继续可读，不改写内容。包含 operation_detached/operation_late 的日志需要 M6 的协议与审计读取端；旧版本遇到未知 kind 应升级，不能删记录降级。新工具调用的能力及 World 身份用于核对原归属。

迁移顺序：升级 Core 及读取/诊断方 → 确认单 Session 单写入者 → 使用旧数据先只读预检 → 对经审定工具显式启用 responsiveness。不要借重建实例、改身份或清空日志解除未结清/未知效果。默认 QQ/TUI 装配没有打开本能力。

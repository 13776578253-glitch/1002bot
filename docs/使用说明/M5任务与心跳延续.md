# M5 任务与心跳延续

任务用于跨触发保留 Agent 意图。当前处理结束后，明确安排可在后续心跳认领；完成、取消和重排由 Agent 结构化提交。架构和验证见 [M5.0](../2026-10-11-M5.0进度与架构图.md)。

## 装配

```typescript
const agent = new ConversationAgent({ sessionId: 'session', tasks: true });
const runtime = new Runtime({ agent, provider, world, session, state,
  heartbeat: { intervalMs: 30_000 },
});
```

沿用现有注入的 Provider、World、Session、State；可从 `1002bot` 导入 Agent/Runtime，从 `1002bot/protocol` 导入 Task 类型和默认容量。任务必须使用提供 scan 的 Session，例如 JsonlSessionStore；心跳需要显式配置。未提供 `tasks: true` 时，ConversationAgent 保持原工具和心跳路径；已保存任务仍可只读查询，不会自动唤醒。

装配可覆盖 `taskLimits` 和 `taskClock`。taskClock 仅供任务到期判断，来源期限仍由 Runtime 的真实时钟负责；正常部署采用默认 Date.now，离线样例使用手动时钟。

同一 Session 同时只能有一个 Runtime 写入者；本批没有跨进程锁或 CAS。重启应先停止旧实例；新实例只恢复事实视图，不恢复旧 Promise 或外部动作。

## 工具与提交契约

| 工具 | 参数与返回 |
| --- | --- |
| agent_task_create | intent、active/waiting、可选 data 和 schedule.wakeAt；返回已确认任务及系统分配 taskId |
| agent_task_update | taskId、expectedRevision，可选 intent/data/status/schedule；省略字段保持原值，schedule=null 清除，wakeAt 重排 |
| agent_task_list | 有界活跃视图，含 items、omitted、selectedTaskId |
| agent_task_read | taskId；查确认活跃/已归档状态，未知身份为 null |
| agent_task_evidence | taskId、runId、可选 bytes；读完整已结清且关联此任务的运行，超限整体失败 |

新任务 revision=1；更新必须匹配当前 revision。安排世代独立：普通内容修订不重新武装安排，显式设置或清除安排才递增 scheduleRevision。任务 completed/cancelled 移出活跃视图，首批不重新打开，后续新任务获得新编号。

内部 TaskRunPort 只出现在当前 AgentContext；Runtime.tasks 只有 snapshot/read/evidence。typed Agent 可直接使用该提交口，但仍须遵守当前 run、generation 和确认屏障。显式工具带原 callId 因果，结束/超时后该调用的权限撤销；旧 run 或旧实例提交返回 task_revoked。

任务工具与 World 工具声明在一次 run 固定并检查名称冲突。Agent 任务工具名称使用下划线，直接兼容现有模型协议名称要求；平台名称适配仍由相应 Provider/装配负责。

## 等待、认领与效果

waiting 不表示执行栈挂起。心跳在确认视图找一个到期且未消费的安排，保存 task_claimed 后再请求模型；记录 checkedAt、scheduleRevision 和 consumedByRunId。重复 tick 不重复旧安排，只有 Agent 明确重排才会再次进入。

认领保存后正常停止，即使没有调用模型，安排也已消费；普通失败同样保持消费。若进程退出导致运行未结清，M4 启动审计阻断，必须先诊断。run succeeded 或工具 succeeded 不自动设置任务 completed。

任务视图包含 lastAttempt 和 effectAttempt。前者是最近关联 run；后者保留最近 World 工具回执的 run，内容修订或新认领不会覆盖旧效果。引用和概要有界，省略会保留实际状态计数与 runId。Agent 任务回执不当作 World 效果。更多细节通过显式完整证据工具进入续轮；默认成功历史过滤不吞掉证据工具的输出。

保存确认后续轮看见本项变更；排队新事实不自动进入当前输入边界。自然语言“我稍后再做”不会保存任务，必须显式结构化提交。

## 容量和错误

`STANDARD_TASK_LIMITS` 默认活跃 64 项/128 KiB 状态、单状态 4 KiB、模型视图 16 KiB、每份尝试概要最多 8 引用且不超过 stateBytes、完整证据 32 KiB。另有每 run 关联数量上限，复用 activeTasks。活跃总状态不计概要，概要另有独立有限预算；终态错误码是有限提示，原始完整原因留在 Session。

task_limit 表示状态形状/容量非法；task_capacity 表示活跃数量/总状态/本 run 关联达到上限；task_conflict 表示修订不匹配；task_claim_conflict 表示安排缺失或已消费；task_evidence_limit 表示完整证据过大；task_revoked 表示提交权失效。当前认领项无法放入模型视图时为 task_view_limit，它不会被无提示省略。

必要 Session 追加失败沿用 storage_error 停止。任务工具的取消/时限不会把内部确认状态归成 World unknown；已进入追加仍等待确认，若完整回执已取得则保留。World 工具效果不明继续 unknown，后续排队项取消；任务安排不能解除阻断或自动重发动作。

归档任务查询从固定确认文件视图扫描，内存有界，延迟随文件增长；显式证据保留整个关联组。没有检查点、归档清理、fsync 或自动恢复动作。

## 离线样例和交互

仓库根运行：

```powershell
node --experimental-strip-types scripts/m5-sample.ts
node --experimental-strip-types scripts/m5-console.ts
```

sample 自动验证顺序感知创建等待任务、到期观察/写入、明确完成、新实例无重复模型。可给目录及 seed / wake / inspect 参数，在独立进程分段验证；crash_claim 是测试故障窗口，会以 23 退出，不用于正常操作。

交互 Console 使用脚本模型、真实文件与手动时钟；输入按以下顺序完成闭环：

```text
input wait answer 7 1000
tasks
advance 1000
read task-1
get answer
tick
restart
tick
diagnose
quit
```

advance 的单位为毫秒，它推进任务时钟并投递一次心跳；tick 只投递心跳。完成后的 tick 没有模型调用。`fact wait answer 8 1000` 使用真实来源发件记录，经 ordered 路径建立另一项任务；控制台只读查询不调用 Provider。EOF 等待已受理项结束再停止。

Console 可提供目录参数以继续使用同一 Session/来源/领域文件。fixture 脚本仅支持演示语法，不代表真实模型的任务判断策略。真实服务手动验收与此离线样例分别记录。

## JSONL 兼容和迁移

M4 的既有 JSONL 可以由 M5 原样读取，不自动改写。启用任务后增加 schema=1 的 task_changed / task_claimed；工具声明/回执添加可选 owner，旧无 owner 的记录按既有 World 路径理解。新任务记录验证 Session、run、generation、触发、调用、单调编号、修订、安排消费与到期依据。

旧 M4 二进制不认识任务种类，会阻断启动；任务日志读取端须升级到 M5。不要删除控制记录或工具 owner 降级，不复制去掉任务状态的半份日志作为恢复。未结清、unknown、owner 配对冲突、损坏和容量不匹配只提供诊断，无自动修复或重放。

任务功能默认关闭；启用它不要求修改生产 World，不依赖长期 Memory 或后续响应性路线。现有 UserInput、World ordered/legacy 身份与控制输出契约保持原入口。

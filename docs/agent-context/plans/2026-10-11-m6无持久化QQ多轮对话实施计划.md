# M6 无持久化 QQ 多轮消息对话实施计划

## 范围

在单账号、固定授权会话内打通 QQ World、Agent、Provider 的纯内存多轮对话。只接受消息事件，继续串行 FIFO；对外回复由 qq.send_text 明确发送，引用回查使用 qq.get_message 的本地快照。新装配实例从干净会话开始。

## 结构

- Core 导出有界 MemorySessionStore，保持串行追加、单条容量、固定长度 scan 及独立读取副本；达到整体容量后明确失败。
- QQJournal 支持显式内存模式，沿用原生身份去重、连续投递与发送意图/确认规则；内存模式不创建 JSONL 或锁。磁盘模式继续兼容。
- ConversationAgent 支持声明 persistent=false；QQ 装配同步选择 Session 与领域记录的内存生命周期。
- Responses Provider 建立合法、可逆的工具线名映射，同步处理声明、通用调用、原生重放和回包；measureRequest 与实际发送共用编码。移除样例层映射。
- QQ 装配明确当前消息载荷已经可读，引用查询只用于需要的历史消息。选择完整已结清历史，使发送成功后普通失败的轮次仍可进入后续判断；整组裁剪、请求容量及输入隔离保持。

## 可交互闭环

消息一触发明确发送；消息二追问能够利用上一轮内容；引用早期入站或已发送消息能够回查。发送后模型普通失败保留真实效果，下一消息仍可继续；unknown 停止。退出并重建装配后，Session、来源序号和领域快照均重新开始。

## 验证规格

真实本地 WS/HTTP、QQWorld、Runtime、Session 与 Agent，脚本化模型响应。校验消息过滤、身份去重/冲突、调用配对、线名重放与发送字节计量、追问与引用、失败轮次效果、新实例清空、容量及取消/资源清理。交付离线交互样例、纯内存生产入口及配置说明、阶段报告。完成闭环后按代码所有者拆分本地提交，不推送。

## 边界

本批默认不启用 Agent 任务工具与心跳；跨轮任务槽位和延时跟进后续接入。完整工具能力属性、自动抢占、挂起恢复、优先级、批处理、媒体理解、多会话调度及长期 Memory 均延后。QQ/SnowLuma 自身的部署数据由外部环境管理；“无持久化”指本装配的 Session 与 QQ World 领域记录。内存确认不提供进程重启恢复，容量值不等于恒定 JavaScript 堆用量。

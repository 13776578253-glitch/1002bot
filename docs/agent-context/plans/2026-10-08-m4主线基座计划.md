| 取舍 | 负责人选择 | 交付边界 |

## 推荐实施顺序

- 按顺序投递设计落实唯一状态所有者、可信登记/稳定 epoch、上游持久信封、去重、背压、保存/结清确认、跨进程重建与阻塞诊断。
- 完成一条纵向闭环：World 保留事实 → sink 受理 → 接收保存确认 → 统一执行 → 结清确认 → 新实例重建 → 重复不重执行、新事实继续。故障/未结清只诊断，不自动恢复。
- 根据增长测量完成流式重建、完整运行组的有界查询及必要 trace 迁移；避免将全历史换存到另一个全量内存索引。
- 补齐混合来源/连续进度/中断窗口回归、旧 JSONL 和配置迁移、公共诊断，以及独立复核与负责人验收。没有相应证据的能力继续待验。

首版缺口明确拒绝并由来源补齐；不隐式跳过或无限缓冲。每流只恢复一个稳定 epoch，不实现动态换代；首次登记确认后才开放来源。事实追加作为进度投影的确认依据，避免假设跨文件原子性。磁盘历史首版不自动删除，资源及拒绝边界明确。

World 待压缩预算包括排队取消/过期后等待追加，以及终态已保存但前缀未越过的位置；连续前缀越过后才释放。工程起始值为 16 个登记流、ordered 位置合计 16；共享排队仍 8。旧 sink/裸 Event/handleEvent 的兼容与迁移单独说明；旧历史缺少流身份时不能自动推导新水位，未具备可信来源边界就不开放该流恢复投递。

## 验收要求

World 不增大 admissionIds 连续跨越旧额度，Console 预算独立；来源实际重建仍按原序号投递，重复/缺口/epoch 契约正确；received 阻塞时 accepted 已返回但 Agent 未执行；确认可查询；连续结清不跨未结清项，前缀后的已结清位置仍占容量；实际新建进程或对象重建进度；动作后回执/终态失败不重放；历史运行组有界且工具配对和原生项完整；M3 FIFO、固定输入、心跳、停止/旧 sink、unknown 与存储失败保持。

状态扩展与文件同步测试不进入本批验收；不能用进程终止实验宣称断电已验收。历史读取候选、trace 和行容量的工程边界按实施设计与规模观察落实。

自动验证不联网，使用真实存储及合理 World 替身；真实 Provider 完整链路另记人工验证。首次生产 World 另定。实现报告遵循负责人阶段汇报规范，M4.0 报告在实现阶段建立，不把本计划命名为已交付基线。

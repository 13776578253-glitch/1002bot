## 推荐实施顺序

- 确认范围后，设计唯一投递状态所有者、可信来源登记/epoch、去重、背压、保存/结清确认、跨进程重建与阻塞诊断。选状态扩展时另补提交版本和请求可见性契约。
- 完成一条纵向闭环：World 保留事实 → sink 受理 → 接收保存确认 → 统一执行 → 结清确认 → 新实例重建 → 重复不重执行、新事实继续。故障/未结清只诊断，不自动恢复。
- 根据增长测量完成流式重建、完整运行组的有界查询及必要 trace 迁移；避免将全历史换存到另一个全量内存索引。
- 补齐混合来源/连续进度/中断窗口回归、旧 JSONL 和配置迁移、公共诊断，以及独立复核与负责人验收。没有相应证据的能力继续待验。

顺序方案首版建议缺口明确拒绝并由来源补齐；不隐式跳过或无限缓冲。ID 索引方案需要可查询磁盘索引，避免全量 ID 常驻内存。事实追加作为进度投影的确认依据，避免假设跨文件原子性。磁盘历史首版不自动删除，资源及拒绝边界明确。

World 未结清预算包括排队取消/过期后等待终态追加的项，确认结算前不释放。旧 sink/裸 Event/handleEvent 的兼容与迁移单独说明；旧历史缺少流身份时不能自动推导新水位，未完成旧事实映射就不开放该流恢复投递。

## 验收要求

World 不增大 admissionIds 连续跨越旧额度，Console 预算独立；重复/缺口/epoch 或乱序 ID 契约正确；received 阻塞时 accepted 已返回但 Agent 未执行；确认可查询；连续结清不跨未结清项；实际新建进程或对象重建进度；动作后回执/终态失败不重放；历史运行组有界且工具配对和原生项完整；M3 FIFO、固定输入、心跳、停止/旧 sink、unknown 与存储失败保持。

若选择状态扩展，验证提交不依赖整轮成功，续轮/下一触发/心跳读取最新已提交版本，保存失败与取消不泄露未提交值。若选择文件同步，验证确认时点与同步失败，不用离线替身宣称断电已验收。

自动验证不联网，使用真实存储及合理 World 替身；真实 Provider 完整链路另记人工验证。首次生产 World 另定。实现报告遵循负责人阶段汇报规范，M4.0 报告在实现阶段建立，不把本计划命名为已交付基线。

建议基座完成后优先最小 Agent 状态与心跳任务延续；生产 World 独立选型，并用真实感知/动作场景检验状态。来源优先级与多事件合并仍是已确认后续目标，具体批次未冻结。自动抢占、领域复核工具、unknown 恢复/重放、长期 Memory、摘要/handoff、多实例、多协议和远程控制仍独立规划。

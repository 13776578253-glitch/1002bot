# M5 持续任务与心跳延续候选计划

形成日期：2026-10-11。推荐范围：跨触发任务状态、Heartbeat 延续和确认重建。本计划描述方案 A 的范围与设计安排，供负责人选择；确认范围后再实施。它不承担执行进度或验收记录。

范围比较：[候选决策清单](../../../scratch/Off-topic%20discussion/2026-10-11-M5候选范围与决策清单.md)。设计分析：[负责人规划报告](../../../scratch/Off-topic%20discussion/2026-10-11-M4后续主线规划与架构演进评估.md)。既有主线计划保持原文。

## 目标闭环

World 或 Console 触发 Agent 建立明确的任务意图与唤醒安排；保存确认后本次 run 结束，Runtime 等待。到期 Heartbeat 读取确认状态，认领一次尝试后由 Agent 决定观察、行动、完成或提交新安排。新实例从已确认事实重建任务，保留 M4 对未结清与未知效果的阻断。

一次认知执行使用现有 runId；taskId 表达跨触发意图。Task waiting 不表示旧 run suspended，不恢复旧 Promise 或 Provider 调用。Task completed 必须来自 Agent 明确决定，不从 run succeeded 或工具 succeeded 自动推导。

## 结构与所有权

- Agent 任务模块拥有意图、任务状态语义和任务工具；Runtime 只验证机械身份、修订、容量、当前 run 权限及提交顺序。
- World 拥有观察数据、领域版本、实际效果和领域校验；生产 World 不承担通用 Agent 任务数据库。
- 扩展原工具装配为小型注册路由，合并 World 和 Agent 任务工具声明并检测名字冲突；执行仍使用原 run/call 配对和时限机制，不引入多活执行框架。
- Session 为任务变更、唤醒认领和尝试证据的事实依据；只有确认追加之后更新投影。
- 当前 MemoryState 的无版本、按引用 get/set 不充当此持久任务契约；新增任务能力需有明确提交口，旧 Agent 未启用能力时保留原路径。

## 身份、版本与容量

任务身份归属 Session，使用独立 taskId。每次任务内容更新使用期望修订，冲突返回明确失败，不覆盖新版本。Task 状态、安排、最近尝试和效果引用分别表示。

明确唤醒安排使用 scheduleRevision；仅创建或明确重排安排时增加，普通描述、进度或附加字段修改不增加。消费身份为 `(Session, taskId, scheduleRevision)`，与 runId 关联，不复用 Heartbeat ID 或 World delivery.sequence。

任务数量、单项状态、最近尝试概要、模型候选字节与诊断均有容量。完成/取消任务进入归档并释放活跃视图名额，不保留无限累计身份集合；旧任务明细按显式预算查询读取。工程起始容量与超限错误在实施契约中给出，参数不作为负责人选择题。

## 提交与可见性

任务工具或显式 Agent 决策产生结构化意图，禁止从普通回复文本自动推断状态。提交检查当前 generation/run 权限和期望修订，启动 Session 追加；确认后发布版本，并保留操作的原因果关联。

状态在运行过程中的安全点更新，无须等待整项任务完成。同一 run 后续续轮可见自己的确认更新；后续触发可见全局确认状态。排队事件的接收归档不进入活动 run 的事实集合，保持固定输入边界。

提交权撤销前已获准并进入追加的提交不因取消回滚，确认后仍发布投影；本次终态和下一 run 不得越过该追加。提交权撤销后才到达的新提交拒绝。必要追加失败关闭受理，不能先发确认再保存。

## Heartbeat 与一次认领

保留单一未结算心跳、期限与积压跳过，不追赶所有 tick。Agent 的低成本入口读取有界确认视图，检查明确 wakeAt 及安排是否未消费；无事返回，不请求模型。Runtime 不判断玩家接近等领域条件。

首版一个 Heartbeat 最多认领一个安排，多个到期项逐次处理，不合并任务批次。心跳 tick 过期或跳过不删除已确认任务与未消费安排，后续合法检查仍可看到它们。

对到期安排先保存一次认领关联，确认且生命周期有效后才调用 Provider/World。后续 tick 不重复派发同一安排，普通失败也不自动重新认领；Agent 必须明确提交新安排。

认领后尚未调用模型就正常停止，安排仍已消费；只有新的显式安排能再尝试。若进程退出导致 run 未结清，仍由 M4 预检阻塞，认领位置不能解除审计。

## 尝试结果与效果证据

任务视图保留有界最近尝试概要、runId 和工具效果引用。失败 run 可能包含真实 succeeded 工具，不能因默认历史只选择成功 run 而隐藏这些效果。显式证据查询应将需要的完整失败组或效果事实实际交付给本次 Provider 请求，保持容量和调用配对。

认领、run 终态、Task 完成、工具效果互相独立。普通模型失败且终态完整保存时，安排仍已消费；unknown、悬空工具、必要记录缺失或存储错误继续沿 M4 停止和预检阻断。

## 记录与启动扩展

设计任务控制记录和认领记录的 schema、因果关联及审计约束；同步 SessionEntry、SessionAudit、历史候选过滤和重建。控制记录不直接重放为模型对话，也不重新推进已结清 World 位置。

首版沿用一条追加事实链及确认投影，不增加独立可写任务真相文件。新实例先完成 M4 与任务投影检查，再开放来源和任务接续；只恢复已确认任务与安排事实，不自动重放旧 run 或工具。文件确认保持追加完成等级，无 fsync 承诺。

## Observation 的初始边界

测试 World 为主动读取与被动 Event 定义共同观察载荷和明确版本域，验证事实与因果来源。World 定义同实体覆盖关系；无法比较的跨来源版本不强制排序。

本批不建立通用高频快照总线、不改变 WorldDelivery 连续序列、不让新观察自动改写活动 run。完整最新投影、独立异步回执、受控抢占及挂起恢复由响应性专项设计。

## 实施组织

先完成端到端契约与一个完整离线交互：输入提出“稍后检查目标” → Agent 任务操作 → 等待状态确认 → run 结清 → 可控时钟到期 → 认领确认 → 新 run 观察/行动 → Agent 更新安排或结束 → 重建与证据查询。

闭环成立后，按工具所有权、状态提交/重建、唤醒/尝试、兼容说明及综合回归拆分交付。任何局部步骤不单独声明全阶段验收完成。实施前处理 M4 复核中影响该契约的发现，并确认下一批范围。

## 验证规格

自动化使用真实 Session、真实本地来源记录、可控时钟和测试 World，只脚本化模型，不联网。交互沿用公共输入和诊断入口，不开发新的 TUI 产品页。

- 单次处理结束后 Task waiting 存在，Runtime 继续运行，ordered 前缀与位置释放。
- 到期检查读确认版本；没有安排或安排已消费时不调用 Provider；重复 tick 不派发第二次尝试。
- 普通字段修订不重新武装旧安排，明确重排才生成新 scheduleRevision。
- 工具 succeeded 后模型/轮次普通失败，旧安排不重复，下一判断收到真实效果依据。
- 状态追加挂起时不提前可见，写入失败关闭受理；取消/停止及旧代迟到更新保持隔离。
- A 的续轮读本项更新，不收到排队 B 的原始事实。
- 干净新进程重建任务、消费事实和最近尝试；认领后未结清、unknown 或损坏保持诊断阻断。
- 新记录与旧 JSONL/旧 Agent 的能力迁移明确，完整工具/原生 Provider 项不拆配对。

验证结果、独立审查与负责人确认写任务记录和阶段报告，不回写本计划。

## 排除范围

自动抢占、Suspended/Resume、多活 Activation、并发工具、高频事实批处理、任意世界快照缓存、未知效果解除或动作重放、长期 Memory、生产 World、fsync、检查点及归档清理不纳入本候选。来源优先级与批处理的后续目标保留，不因本批保留 FIFO 而取消。

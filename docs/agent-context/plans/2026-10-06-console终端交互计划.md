# Console 终端交互计划

状态：2026-10-06 首批同进程 TUI 原型已实现，自动验证和 Windows PTY 操作已完成；负责人确认 M2.1 人工验收通过，要求本轮提交推送远端并同步 main。本计划继续跟踪后续目标与分批验收，尚未整体完成。M2 首批终端交互继续作为已验收兼容基线。

## 产品定位

TUI 将长期保留，作为通用基座的前端之一，目标包含特定 World 交互/监控、输出、配置设置与 Agent 总运行监控。未来其他终端、Web、Desktop 或移动端共用稳定控制接口。当前同进程原型只交付已有 Console 输入与运行反馈，其他能力仍需明确公共契约。

默认视图围绕持续活动组织；一次输入、事件或工具调用结束后，Runtime 可以继续等待下一触发。

负责人已明确全屏终端方向，并以 Claude Code 的全屏操作体验作参考；样式、边界围栏和 coding-agent 产品定位不作为目标。界面不以代码目录、文件修改、diff 或“完成整个任务”组织主流程。

Console 单独负责界面和操作反馈。[链路工作线](2026-10-06-链路逻辑推进计划.md) 负责 World Event、Console 输入、Heartbeat 的公共受理、调度、执行与记录。Console 交互优化不阻塞链路推进。

## 基线与独立开发方式

现有入口为 `src/console/terminal.ts`、`scripts/console-sample.ts` 和 [使用说明](../../使用说明/终端Console.md)。可复用公共能力为 `RuntimeControl`、`InputChannel`、`OutputEvent` 与生命周期接口；M3 已交付统一触发，前端目前仍只提供既有输入控制与公开活动展示。

独立开发现位于 `packages/apps/tui/` 包，`examples/tui/sample.ts` 为离线组合入口，交互状态和验收记录分别保留。运行 `pnpm dev:tui` 进入离线样例，`pnpm probe:tui` 检查实际按键与终端尺寸。现有行式 Console 继续支持脚本和非 TTY 输入输出。操作见 [全屏 TUI](../../使用说明/全屏TUI.md)。

首批采用同进程装配 Runtime，通过适配器访问公共接口；后台连接另设连接与生命周期契约批次，定义断线、重连、快照和退出是否停止后台。独立模块与独立进程分别验收，分进程能力尚未实现。

## 首批操作场景

| 场景 | 目标行为 |
| --- | --- |
| 持续观察 | 看到 Runtime 状态、当前处理和可查询的排队情况；无活动时显示等待触发 |
| 输出期间编辑 | 新输出更新活动区，草稿、光标和编辑焦点保持；活动输入执行时仍可编辑下一条 |
| 连续提交 | 正文提交后显示关联条目与受理回执；拒绝时保留正文及原因，允许修改后再提交 |
| 回看活动 | 滚动到历史时暂停自动跟随，新活动只更新未读提示；返回底部后恢复跟随 |
| 检查一次处理 | 从条目查看完整关联标识、模型轮次、工具回执、最终结果和记录写入状态 |
| 控制运行 | 本地命令显示执行中与成功/失败反馈；取消请求和最终取消分开展示 |

状态由公共回执、诊断和快照驱动。界面不把“提交成功”当成执行成功，不把 `tool_finished` 当成已落盘，不把一轮成功当成整个 Agent 停止。`write_pending`、`persisted=false`、`unknown` 和停止中必须可辨认。

## 主视图与交互草案

全屏布局按阅读顺序提供运行状态、活动时间线、输入编辑区和简短操作提示。使用留白、对齐和有限颜色区分信息；状态同时提供文字，首批不添加大面积框线、ASCII 围栏或固定侧栏。诊断在选中条目的详情视图展开，窄窗口优先保留输入和当前状态。

活动区是一条持续时间线，输入、回复、工具活动和本地命令反馈保持关联。普通视图显示可读摘要，详情保留完整 ID、轮次、错误码及原因。当前只显示已有公共数据；统一契约落地后再接入 World Event 和 Heartbeat，不能用本地模拟状态冒充实际运行。

输入区支持自然多行、光标编辑和粘贴。首个原型采用 Enter 换行、Ctrl+S 显式提交，已在 Windows PTY 验证；大段或多行粘贴只进入草稿。本批负责人实际终端验收已通过；其他终端组合的输入法与按键兼容性另行验证。

本地命令与正文的区分沿用 `/command` 和 `//` 转义；全屏中多行草稿的提交操作替代 `/begin`、`/send` 编辑流程，旧行式入口保留原行为。命令参数、目标和结果直接显示；未知命令保留输入以便修正。

| 操作 | 拟定语义 |
| --- | --- |
| 提交正文 | 按公共受理回执更新界面；受理前不提前清空草稿，单次提交期间阻止同一草稿重复发送 |
| 打开详情、返回 | 只改变本地视图；返回后保留草稿和回看位置 |
| Esc | 关闭帮助或详情、返回编辑；不隐式取消 Runtime 执行 |
| `/cancel [ID]` | 指明目标；省略时仅在当前可确定的活动 Console 输入上执行，否则提示指定 ID |
| `/status`、`/inspect ID` | 展示公共状态；缓存淘汰显示不可查询，事件缺口显示记录不完整 |
| `/stop`、`/start` | 请求 Runtime 生命周期操作；反馈以实际完成或失败为准 |
| `/quit`、Ctrl+C | 首批同进程方案沿用停止并退出；等待写入收束时保持状态展示，完成后恢复终端 |

首个原型使用 Tab 切换焦点、PgUp/PgDn 翻页、F2 详情、F1 帮助、Esc 返回输入和 Ctrl+L 跟随。草稿仅在本进程保存；输入历史导航后续定批。

## 模块职责与公共接口

| 模块 | 职责 |
| --- | --- |
| 终端输入与显示驱动 | 按键、粘贴、终端尺寸、字符宽度、屏幕重绘与退出恢复 |
| Console 交互状态 | 草稿、光标、焦点、选中条目、滚动位置、未读提示和展示缓存 |
| Console 公共接口适配器 | 提交、取消、查询、订阅和生命周期调用；将回执转换为界面状态 |
| Runtime 公共契约 | 提供实际受理、执行、诊断和生命周期事实，由链路工作线维护 |

TUI 不直接调用 Agent、Provider、World 或 Session，不另建执行队列、不推断工具结果、不自动重试已受理输入。界面状态与 Runtime 事实分开保存，展示排序使用公共事件顺序及关联标识，不能靠屏幕文本解析业务状态。

首个原型保留最多 128 条/512 KiB 活动，文本与详情字段各约 16 KiB、草稿 64 KiB。事件合并重绘，输出背压期间保留最新状态；活动折行按宽度缓存。缓存淘汰不改写草稿，选中条目不可见时显示淘汰提示。持续心跳聚合在公共语义确定后设计。

现有接口不足以保证附着到运行中 Runtime 时取得完整队列与活动快照；现有 `pending` 仅统计本 Console 已受理的输入。界面不得将其标成全局队列数。向链路工作线提出的需求包括统一来源与关联、当前活动与排队快照、订阅衔接和缺口识别；实现前逐项确认可用性，不预先改动其接口。

## 2026-10-08 已确认的包隔离要求

TUI 作为独立可选前端，与未来 WebUI 并列，拥有独立 package.json、源码目录、依赖与构建/检查入口，由 pnpm 管理整套或单包安装。核心必须可以单独安装和运行，不要求安装 OpenTUI、React 或 TUI 所需运行时。

当前执行边界已有公共接口隔离，但安装与构建仍合并在根包：string-width 是根运行依赖，测试和类型检查扫描整个 src，TUI 引用行式 Console 实现及其中定义的 ConsoleRuntime。迁移需要同时处理依赖归属、公开导出、启动装配、测试与类型检查，目录移动不能单独满足验收。

讨论方案：使用 pnpm workspace，将核心、已有公共控制契约和 TUI 分为独立包；核心与 TUI 单向依赖公共契约，组合入口选择装配。框架类型和终端实现不进入公共契约。具体目录、包名、行式 Console 归属及整套安装入口尚未冻结；单包发布、运行时选择和分进程连接另行确定。

后续验收应使用干净目录分别检查核心单包安装/运行、TUI 单包安装与包入口、整套组合运行、各包独立检查及现有交互回归。workspace 默认安装范围和共享锁文件解析行为需按项目采用的 pnpm 版本验证，不能只依据 filter 名称宣称无前端依赖下载。本轮只记录目标与方案，没有移动源码、修改清单、安装框架或实现主线能力。

## 2026-10-08 核心位置、内部 Console 与包分类讨论

已确认：行式 Console 收束在 src/console，仅作为内部测试入口；未来有成熟测试替代时考虑删除。正式 TUI 独立可选安装的目标保持。

方案更新：核心可以继续由根 package.json 与 src 持有，无须为此次前端隔离整体迁入 packages/core。根包运行依赖、导出与检查范围必须独立于可选前端；根 workspace 的全量调度命令与核心自身的检查命令分别定义。

统一控制入口属于核心公共能力。若 src/console 专用于可删除的内部测试，建议将公共控制实现/导出放入 src/control，控制契约按实际独立分发需要放入轻量共享包；名称与物理位置仍为候选。核心与前端共享一个契约定义，各自承担控制实现与界面入口；当前同进程直接传入已有能力对象，不要求两侧重复封装适配器。

目录候选：packages/apps/tui 与未来 apps/webui 表达可选应用；packages/extensions 放未来独立扩展；packages/shared 放有实际复用或分发需求的轻量契约。packages 是独立安装/构建/发布单元的容器，不要求所有模块包化。分类目录自身不是包，各实际包才持有 package.json；尚未实现的应用或扩展只保留方案，不创建空包或加载机制。

迁移注意：当前 TUI 非 TTY 回退直接调用 src/console/terminal.ts 的 runTerminal。内部测试入口未来可删除，因此独立 TUI 不应继续依赖它；非 TTY 行为需在迁移前单独确定归属与兼容要求。本轮不修改现有回退行为、接口、源码或包清单。

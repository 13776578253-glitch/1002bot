# M6 受控响应基座实施计划

## 范围与闭环

在一个 Session、一个 Runtime 写入者和单逻辑 run 下，允许操作者明确结束只读/模型等待中的 A。A 的必要回执和终态确认后，按原 FIFO 启动下一项；原外部操作晚到时独立归档，不进入当前或以后 run 的自动上下文。动作和能力未声明的 World 工具保持保守取消、unknown 停止。

通过可交互离线终端完成“阻塞观察 A → 受理 B → 明确让出 A → B 处理 → 释放 A 原结果 → 查询迟到证据”的完整闭环。同时证明物理调用名额、存储屏障、任务安排消费、观察版本和停止/重启边界。

QQ 任务/心跳接入、自动抢占、优先级、批处理、暂停恢复、多活执行与长期 Memory 不在本计划。默认装配继续兼容；M6 通过 RuntimeOptions 的响应性配置显式启用。

## 协议和所有权

- World 工具可声明可信效果能力；首批只审定不改变外部业务状态的只读能力。声明来自实现，随本 run 的工具所有权表固定。缺省能力仍按效果可能未知处理，模型无法覆盖能力。
- ToolExecutionContext 增加原 Session/run/call/触发因果信息；generation 继续表示实例提交权限。调用正常返回要求 World 已收回该调用自有本地资源，不在返回后隐匿后台监听/任务。
- Runtime 拥有单逻辑执行位、明确让出控制、所有外部 Provider/World 调用的有限登记和独立迟到追加权限。
- 明确控制以当前 runId/generation 为目标，拒绝旧目标、动作等待或名额不足。控制回执表示请求受理，run_finished 表示真正收束；原 cancel/stop 保留强制取消语义。
- 原 ToolOutcome、任务提交、run 终态和迟到记录是不同事实。取消不撤销已经取得的真实回执，也不归还已消费的 task scheduleRevision。
- Agent 可通过有限只读入口显式查询原调用迟到证据；可选 Agent 证据工具复用既有 owner 分流。迟到数据不自动拼入普通历史。

## 操作登记、迟到和容量

登记使用原 run/call 或 Provider 轮次，无同义 activationId。登记先于真实调用，外部调用 Promise 结束才释放物理名额；AbortSignal 和时限只结束逻辑等待。普通返回后仍须验证回执归属，动作未验证期间不允许安全让出。

标准全部在途调用上限为 3；主动让出最多保留 2 个原调用。强制停止期间可能撤销剩余活动调用，仍受全部在途上限约束。达到边界明确拒绝新调用或让出，不创建无限后台 Promise，也不以 TTL 删除登记冒充资源退出。

只读调用被逻辑放弃时，先确认独立撤权登记，再提交普通 cancelled 回执及终态；其晚到成功、失败或超限原因走原调用独立记录。Provider 晚到只保存有限诊断，不调用其中工具或保存大响应作为未来上下文。动作 unknown 不因底层后来成功而解除。

迟到记录单条和显式查询各 32 KiB，待确认迟到追加合计 128 KiB，按 UTF-8 JSON 计量。超限保留有界原因与原身份，不截断为伪完整观察。必要记录失败关闭受理并停止；记录序列化时固定数据副本。

## Session、审计与历史

新控制/迟到记录使用独立 origin 关联，不通过顶层旧 runId 打开历史活动组。工具调用保留原能力依据。Audit 核对原调用、能力、撤权和一次迟到结算，重复/错配/缺少确认阻断；未结清撤权记录不会被忽略或自动恢复。

HistoryWindow、ConversationAgent 和任务投影过滤独立操作记录，保留原普通已结清组。显式证据查询使用 scan、原因果和完整字节预算；Agent 执行时读权限同样受本 run 信号约束。

旧日志可读；写入新记录后需升级读取端，不自动删除记录降级，不重放外部动作。MemorySessionStore 和 JSONL 共用新协议，必要扫描能力在启用时校验。

## 停止和权限

stop 同步撤销新调用和来源，收束通道与已经进入的必要追加，再结清登记和归档。启用响应性时，资源清理超时/错误明确失败，未完成的旧实例保持停止中并拒绝新启动；调用或 World 后来退出后可以显式再次 stop 结清。必要存储本身永不返回仍不能被资源期限跳过。

迟到追加只属于 Runtime 停止前取得的原操作登记。完整停止后无旧代写权，新实例不能接续旧 Promise。原 World 清理、通道终态与操作归档都必须检查，不能以 stop 返回或计时到期冒充资源已退出。

## 观察与世界边界

固定输入和 FIFO 保持。World 自己定义实体、版本域和最新快照覆盖规则；用真实文件测试 World 证明较旧主动观察迟到不覆盖较新被动事实。投递 sequence、时间戳和 QQ 消息号不充当通用状态版本。

首批不建立通用最新缓存或自动复核调度。不可撤回动作的复核工具/版本前置条件继续由 World 实现和 Agent 选择。

## 实施与验证安排

先落实协议、操作登记、执行/控制、审计与显式证据，再形成离线终端和交错闭环。只在闭环可交互且验证完成后按代码所有者拆分交付，提供独立 M6.0 报告、迁移说明、英文职责锚点和中文契约/机制注释。

验证覆盖：正常读/写；A 让出后 FIFO；晚到成功/失败/超限和不透明 Provider 结果隔离；回执与取消竞争；动作和旧能力拒绝安全让出；强制取消 unknown；重复控制与有限资源；任务认领后让出不重试；记录写入阻塞/失败；旧代权限；停止失败后禁止重启；新记录预检、旧日志兼容、重复归档；观察版本。使用真实 Session、文件 World、临时进程与必要回环端口，仅模型决定脚本化，不启动真实 bot。

# M5 跨触发任务与心跳延续实施计划

设计日期：2026-10-11。范围为路线 A：跨触发任务状态、明确唤醒安排的一次认领、尝试证据和确认重建。前期范围见 [候选计划](2026-10-11-m5持续任务与心跳延续候选计划.md)。本文件保存范围、契约与实施安排；执行、验证和验收写任务记录及 M5.0 报告。

## 交付闭环

Console 或 World 触发 Agent 创建任务 → 意图及安排保存确认 → 当前 run 结清 → 到期 Heartbeat 检查确认状态 → 保存一次认领 → 新 run 观察或行动 → Agent 明确完成、取消或重排。普通 run 失败不重新派发旧安排；新实例重建任务与消费事实，未结清和 unknown 继续阻断启动。

保留严格 FIFO、单活动项和固定输入边界。taskId 表示跨触发意图，runId 表示一次有界处理；任务等待不保持旧 Promise，工具成功和 run 成功不自动完成任务。生产 World 与 QQ 装配独立，本批用真实本地来源与测试 World 验证。

## 所有权与公共接入

Agent 提供可选任务工具集及低成本心跳策略；未启用时保留旧 Agent 路径。Runtime 提供当前 run 的任务提交口与只读检查口，检查权限、修订、容量和保存屏障。World 保持领域事实与外部效果所有权，Session 是任务事实的唯一持久依据。

工具注册按一次 run 固定声明，将 World 与 Agent 任务工具合并并拒绝重名。任务工具不进入 World 副作用不明窗口；提交进入追加后等待确认，不能以工具时限截断必要写入。World 的取消/超时仍按原 unknown 规则处理。

## 任务与记录契约

- taskId 由提交口分配 Session 内单调编号，重建保留分配尾部；完成/取消从活跃视图移出，不保留累计 ID 集合，不复用旧编号。
- 状态为 active / waiting / completed / cancelled；字段包含意图、有限 JSON 数据和 revision。新任务期望修订为零，更新携带 expectedRevision；终态任务首批不可重新激活。
- scheduleRevision 独立于内容 revision。显式设置或清除安排才递增；描述/数据/状态修改保留原安排消费事实。安排包含 wakeAt 与可选 consumedByRunId。
- `task_changed` 和 `task_claimed` 采用 schema 1，记录 Session、run、generation、触发和可选 call 的因果关联；认领保存 checkedAt 作为任务时钟的到期依据。工具声明/回执保存 owner 并审计配对。完整快照保存意图/安排；尝试结果由同 run 的真实工具与终态事实投影，不由模型自报效果。
- 任务变更保存确认后才更新投影。撤权后新提交拒绝，撤权前已经进入追加的提交继续确认；收束和下一 run 等待已进入提交。必要追加失败关闭受理并停止。
- task_changed 关联该 run 的最近尝试；task_claimed 关联消费身份 `(Session, taskId, scheduleRevision)`。控制记录不作为新输入，也不改变 World 已结清序列。

## 心跳与模型可见性

任务 Agent 检查有界确认视图，按 wakeAt / taskId 选择一个到期且未消费的 waiting 任务。无任务时不调用模型；自定义既有 heartbeat 策略仍可作为无到期任务时的显式策略。Runtime 提供可控的任务时钟，心跳积压/过期机制沿用 M3/M4。

认领先保存，再构造请求及调用 Provider。保存后即使正常取消且尚未调用模型，安排也已消费；重新尝试必须明确重排。进程退出导致未结清时保持 M4 阻断。普通字段更新不能重武装旧安排。

模型请求附带有界任务视图和 selectedTaskId，优先包含当前认领项，说明省略数；同 run 续轮看见自己的确认变更，不吸收排队输入。lastAttempt 表示最近关联运行；effectAttempt 单独保留最近具有 World 工具回执的尝试，任务内容修改或新认领不会抹掉旧效果。引用超限保留真实状态计数、runId 与 omitted；Agent 任务回执不混作 World 效果。显式证据工具读取完整、配对、已结清的关联运行，整体超限则拒绝；证据通过工具回执实际进入续轮，不受默认成功历史过滤。

## 初始容量

| 参数 | 默认设计 | 超限行为 |
| --- | --- | --- |
| 活跃任务 | 64 项 / 128 KiB 状态合计 | 拒绝新建或更新，不淘汰未完成任务 |
| 单任务状态 | 4 KiB UTF-8 JSON | 明确拒绝，不截断意图或数据 |
| 模型任务候选 | 16 KiB | 按完整项裁剪，当前认领项优先，报告 omitted |
| 最近工具引用 | 每尝试 8 项，概要不超过 stateBytes | 保留最近引用与真实总数并计 omitted，原事实仍在 Session |
| 显式证据 | 32 KiB 完整关联运行 | 整体拒绝超限，不拆工具/原生项 |

所有参数可装配覆盖且验证正整数。已归档任务查询扫描已确认 Session，内存保留活跃视图及一个目标任务；磁盘归档增长和扫描成本不承诺恒定。首批不增加第二份任务文件、检查点、自动清理或 fsync。

同一 Session 使用单 Runtime 写入者；首批不提供并发进程锁或分布式 CAS。概要错误码只作有限提示，终态加入后仍按整份概要预算检查，完整原因保留在原事实。

每任务至多保留 lastAttempt / effectAttempt 两份概要；单 run 至多关联 activeTasks 个任务，防止循环完成/新建在 run 结束前积累无界终态对象。模型候选按完整项裁剪；当前认领项若无法容纳则明确失败，不偷偷省略。工具期限撤销该调用的新提交权，已进入追加仍等确认；回执已取得则保留它。

## 重建与迁移

启动在 World.start 之前一次扫描，同时审计执行与任务记录，验证 schema、Session、单调编号、期望修订、安排/认领、当前 run 和容量。新实例只重建已确认状态，不恢复旧执行栈。启用任务需要 Session.scan；旧 Agent 与不含任务记录的旧日志保持原行为。

不含任务记录的 M4 JSONL 可直接读取；新增记录后旧 M4 二进制会拒绝未知种类，应升级读取端，禁止删记录降级。不自动转换其他任务格式，不解除 unknown、未结清或损坏。

## 实施与验证规格

先贯通协议、确认投影、任务工具、低成本心跳和一个离线样例，再完善故障、重建、容量、迁移与包兼容。提供可手动输入、推进时钟和重启的离线终端样例，使用既有 Runtime 接口。初始样例使用共同的被动/主动 Observation 载荷，World 声明实体和版本域，不建立通用观察缓存或最新状态总线。

自动测试使用真实 Session 与来源记录、可控时钟、测试 World和脚本模型。覆盖：

- waiting 保存后 run 结清、顺序位置释放；到期接续后明确结束或重排。
- 重复 tick 无二次认领；普通字段修改不重武装；多个到期项每次只处理一个。
- 工具成功后模型普通失败，旧安排不重跑；后续请求收到真实成功效果，显式完整失败证据进入续轮。
- 保存阻塞时状态不可见，失败停止；撤权前进入追加仍确认且终态等待，撤权后迟到提交拒绝。
- 活动 A 续轮看到本项更新，排队 B 原始输入不可见。
- 干净新实例及独立进程重建；认领后异常退出、unknown、损坏、错误修订/消费关系阻断启动。
- 活跃容量、归档释放、旧任务有界查询及完整证据超限；工具名冲突不进入效果执行。
- 全工作区类型检查、聚合测试、M1/M3/M4/M5 样例和必要包隔离检查。

## 排除范围

响应性路线 B、自动抢占、Suspended/Resume、多活执行、并发工具、优先级与批处理、高频快照总线、异步回执、长期 Memory、生产 World、unknown 解除、动作重放、fsync、检查点及归档清理不纳入本批。优先级和批处理保留为后续目标。

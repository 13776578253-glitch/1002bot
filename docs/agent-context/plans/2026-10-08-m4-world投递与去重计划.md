# M4 World 投递与去重计划

日期：2026-10-08。状态：负责人已明确要求 M4 实现；本页记录目标、待设计契约和验证要求，尚未修改 M4 生产代码，具体机制未冻结。

## 问题与实现基线

M3 已验收统一受理、FIFO、World sink、心跳和故障收束；内部心跳以 Runtime 生命周期身份运行，不占外部 ID 集合。讨论提出的 World 专门投递/去重契约未落实：World Event 与 UserInput 仍以 `(kind, id)` 放入同一个 seen，共享 admissionIds 默认 4096 累计预算。

默认值可配置，但累计身份完成后不释放，同实例重启也保留。提高预算只是延后耗尽；World 消耗额度也会阻止新的 Console 输入。M3 已公开该容量边界，当前进一步明确为讨论目标与实际实现的偏差。负责人指定在 M4 解决，M3 限定首批验收结果保留。

基线证据：[M3 阶段报告](../../2026-10-08-M3.0进度与架构图.md)、[原决策清单](../../../scratch/Off-topic%20discussion/2026-10-06-M3架构路线与待决策清单.md)、[任务记录](../current-task/2026-10-06-m3统一触发调度.md)。

## 交付目标

- 定义并实现 World 专门投递/去重契约，解除 World 与 Console 的共享累计身份额度耦合。
- 保留 UserInput 既有精确 ID 承诺；World 的长期机制依据来源实际投递约束定义，不通过静默淘汰 ID 再次允许旧动作。
- 在有界资源条件下支持契约覆盖的持续 World 输入，明确允许的重复范围、乱序、来源重启和进度保留；不能同时承诺任意 ID、永久精确去重与有限内存而不提供额外来源约束或存储。
- 保持 M3 的接收追加确认后执行、FIFO、固定输入边界、代次隔离、最终结果和 unknown 停止规则。

## 投递契约需要先确定什么

| 契约位置 | 必须明确的问题 |
| --- | --- |
| 来源身份 | 装配的 World、逻辑来源与产生者实例如何识别；可修改的 source 标签不能自行授予新去重命名空间 |
| 序号/游标 | 来源是否提供单调序号，哪些事件共享序列，是否允许乱序、空洞或重复投递 |
| 来源重启 | 同一来源的新 epoch 如何建立，旧 epoch 的迟到项如何拒绝，进度和资源怎样保留或释放 |
| 回执与来源保留 | accepted 继续只确认内存受理；来源保留至哪个保存/交付确认点，如何观察该点，拒绝如何缓冲或限速 |
| 提交与可见性 | 接收记录保存、事实交付给 Agent、本项处理结束和外部动作生效各用什么事实证明 |
| 进度推进 | 使用处理水位时只能越过连续已结清前缀，不能用最大已见序号跨过较早未处理项 |
| 崩溃与重启 | 明确跨进程进度是否保证及其存储确认；不把内存 accepted 提升为断电持久承诺 |
| 容量与拒绝 | 活动来源、乱序区间、窗口或存储索引的边界及超限回执；World 的机制不消耗 Console ID 预算 |

去重应有唯一状态拥有者与提交入口。World 提供来源语义和投递约束，Runtime 执行对应的机械受理；不能让多个 handler 各维护一套无法对照的处理进度。

## 候选机制与取舍

| 候选 | 可承接的来源约束 | 需要付出的保证或代价 |
| --- | --- | --- |
| 来源单调序号与进度 | 来源能提供稳定序列和重启身份 | 需要连续前缀、乱序/空洞和尚未结清集合，不能直接保存最大序号 |
| 明确滑动去重窗口 | 来源承认有限时间或序号范围内的重复检测 | 窗口外重复可能再次被受理，必须公开政策并确认动作风险 |
| 持久游标或身份索引 | 必须跨进程保留受理/处理身份 | 明确保存确认、查询成本、故障窗口及结构迁移；不自动构成外部动作事务 |

以上候选不能按参考项目存在某个机制就整体复制。先用测试 World 建立明确来源契约，再实现能满足它的方案；首个生产 World 的产品选择仍独立确定。

## 迁移与实现要求

- 分离 World 与 UserInput 的身份状态/配额归属；明确现有 admissionIds 配置的兼容含义与旧契约的迁移方式。
- 保持原 JSONL 可读。需要新增来源身份、进度或保存确认时，说明记录 schema、确认点与失败收束，不能把旧记录臆造为已有持久处理水位。
- 去重判断不能把“收到过”混同“已处理”。进入内存、记录保存、Agent 可见和动作生效分别说明；World 同一事件产生多个工具动作时尤其不能用一个 ID 掩盖中途 unknown。
- 不自动重放工具副作用。持久化进度不代表已经解决动作后回执丢失；效果不明仍停止并提供诊断。
- 不以扩大 4096、每轮清空 seen 或快照淘汰作为交付完成条件。

## 验证与验收

自动验证不联网，使用真实 Session/进度存储、测试 World 与脚本模型。验证行为和外部效果，不能仅断言某个集合被替换。

- World 连续受理和处理跨越旧累计预算，身份状态符合声明的资源边界；不依赖扩大 admissionIds 通过。
- World 长时输入不耗 Console 的独立 ID 配额；Console 的重复输入仍按原契约拒绝。
- 重复、乱序、空洞与来源重启符合选定契约；较新项完成不跨过较早未结清项，旧 epoch/Runtime 代次迟到项不影响新处理。
- 对接收追加、进度保存、执行和终态提交分别构造故障窗口；来源重投时不会把未确认效果当作明确失败自动重复执行。
- 保持混合来源 FIFO、活动处理不自动取消、固定输入边界、心跳未结算名额和 unknown 停止回归通过。
- 若承诺跨进程进度，实际关闭并重建存储/Runtime 验证，而非仅同实例 stop/start；丢失或重复窗口如实记录。

交付记录包含设计选择、结构变化、迁移、自动验证、独立复核与负责人验收。规模和性能成本先测量，再决定是否需要索引、快照或存储更换。

## 范围边界

本计划明确承接 World 投递与长期去重偏差。优先级和多事件合并仍是后续目标，World 复核工具按实际领域风险设计，具体批次未冻结。Memory、生产 World 选型、unknown 恢复/动作重放、通用持久积压恢复、摘要/handoff、多实例和多协议切换不自动进入 M4。

## 首批目标

后续设计必须遵循 [持续运行 Agent 设计约束](../../../scratch/Off-topic%20discussion/持续运行Agent设计约束.md)：1002bot 由事件和心跳驱动持续运行，单次处理结束不代表 Agent 完成任务或停止；事件、模型与工具记录随运行过程及时追加，Memory 持续更新并供后续触发与续轮读取。此约束明确运行模型，不表示心跳调度或长期 Memory 已进入首批交付；具体契约和批次仍待设计。

用户通过独立 Console 连续提交输入，经通用输入通道进入 Runtime，由生产 Agent 组装上下文、调用 Provider 并返回结果。第二次输入保留容量范围内的前文；需要工具时，经 Runtime 调用已挂载 World 的工具并回填结果。

保留单 Bot、单主 Session、单 World 和 `src/runtime/compose.ts` 唯一组合根。首批用现有 FixtureWorld 验证工具链路；测试样例的装配仍属于测试基础设施。首个生产 World 的选型与验收另立任务，不作为 Console 输入闭环的前置条件。代码复用或迁移按模块单独裁定。

## 模块边界

| 模块 | 所有权 |
| --- | --- |
| Console 控制台 | 提交用户输入、显示 Agent 输出与运行诊断；通过公共契约接入 Runtime。界面与进程形态待定。 |
| 通用用户输入通道 | 规范输入身份、来源、接收结果与取消语义，供 Console 及未来其他输入端使用；不要求输入端实现 World。 |
| Runtime | 接收输入与 World 事件，串行处理同一 Session，管理队列背压、生命周期、请求/工具时限和工具调度。 |
| Agent | 通用消息组装、上下文容量策略和 Session 声明；使用契约提供的工具集合，不依赖具体 Console 或 World。 |
| World | 环境事实、工具声明、领域校验与工具执行。用户输入的接入不改变具体环境与工具的所有权。 |
| Assembly | 装配 Console、输入通道、Agent、Provider、Session、State 与选定 World；实际装配选项在实现阶段确定。 |

## 首批交付与验收

| 能力 | 交付与验收 |
| --- | --- |
| 独立 Console 与用户输入 | 连续提交两条相关输入并显示回复；相同输入契约可由测试输入端调用，验证 Runtime 无 Console 或具体 World 依赖。 |
| 串行处理 | 同一 Session 的输入按接收顺序执行；明确队列容量、背压与停止时待处理输入的结果。覆盖连续输入与停止竞争。 |
| 生产 Agent | 通用消息组装与工具声明接入；跨输入保留完整工具调用/结果配对，复用已验证 Responses 往返。 |
| 上下文容量上限 | 提供明确、可配置且可验证的上限；固定计量方法、预留额度和超限行为。当前输入、未完成调用和 Provider 必需项不得拆散；无法容纳时返回可诊断结果。首版不生成摘要或进行 handoff。 |
| 请求与工具时限 | 固定 Provider/工具 deadline 与最大轮数，区分超时和用户停止。外部副作用无法确认时保留 unknown，不自动重试工具。 |
| 运行诊断 | 显示输入、轮次、callId、错误、unknown 与停止结果；凭据和 Provider 隐藏输出不进入常规终端日志。unknown 只提供状态与原因，不提供恢复、重试或重放入口。 |
| 本地运行入口 | 提供使用脚本 Provider 和 FixtureWorld 的可交互样例。真实 Provider 工具往返保留单独的手动验收入口。 |

首批继续使用现有 JSONL Session 和内存 State，不新增事件持久化或持久 State，也不承诺重启后继续未完成轮次。存储失败对用户可见；停止前已提交写入结束后才允许重启。

自动化验证使用脚本模型、真实本地存储与通用输入契约，不连接外部网络。首批完成后独立 Review，并由负责人验收可交互闭环。

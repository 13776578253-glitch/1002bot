# M2 首批闭环方案设计

Time: 2026-10-05

Authorization: 项目负责人要求以实现逻辑闭环为首要目标，界面形式、输入契约与容量参数由 AI 自行设计，形成具体方案后交由负责人选择。本次提供方案与交互原型，不开始 M2 生产实现。

Change: 设计统一的输入受理、串行处理、完整模型/工具往返、输出关联、取消/停止与容量失败语义。提供对话控制台、终端会话和运行工作台三种界面方案，以及明确的容量默认值与可选预设。

Impact: Console 作为独立输入/展示端，通过公共契约接入 Runtime；World 所有权与选型保持独立。逻辑闭环不依赖界面形式、真实 World 选型或新持久化模块。

Verification: 对照 M1 现有协议、组合根、Runtime 停止屏障与 Provider 输出项回传；逐项检查受理/拒绝、FIFO、终态、取消、late callback、存储错误、context_limit 和 unknown 是否有明确落点。原型使用本地模拟状态，不访问服务。生产代码与既有测试保持原样。

Open issues: 界面方案与容量预设等待负责人选择；输入契约给出推荐设计与精简替代设计，不把推荐视为已批准。

Update: 已完成 `agent-context/plans/2026-10-05-m2闭环设计与选型.md`，给出三种独立 Console 界面、推荐输入契约和精简替代、紧凑/标准/宽裕容量参数。明确 FIFO、受理内存语义、ID 去重、一次性终态提交、生命周期取消记录、原始 Provider 项保留、按完整轮次裁剪和无法确认工具的诊断/停止语义。推荐对话控制台 + 受理回执/输出事件 + 标准容量；范围草案已指向附件，参数尚未冻结。

Prototype verification: 本地交互原型已检查脚本语法、发送、排队、停止/启动、终端命令、工作台、context_limit 与 unknown 演示，浏览器无脚本错误；1056、736、360、320 像素宽度无横向溢出，并检查桌面与窄屏截图。原型采用模拟响应，没有接入 Runtime 或真实 Provider，不能充当生产闭环的验收。一次性 QA 脚本位于 scratch/check-console-options.cjs。未修改 src 或既有 tests，未重跑 pnpm 测试。

Design verification: 所有已受理输入在进程正常存活且存储可完成的前提下有一次终态；明确进程崩溃、存储永久挂起和忽略取消的 World 不能由内存回执保证收束。被拒绝输入不启动模型或工具；未知结果和容量超限不重放已执行工具。界面、契约和容量等待负责人选择。

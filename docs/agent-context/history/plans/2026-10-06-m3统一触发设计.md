## 已确认的受理与调度决定

- `accepted` 在内存受理后返回，不等待接收记录追加确认。执行仍等待接收记录追加成功；回执不表示保存成功或执行完成。
- 本批按 FIFO 逐项执行，新事件不自动取消活动处理。显式取消与停止保留控制通道。
- 来源优先级和批处理为后续目标，本批不实现；分别确定公平性、批次归属与合并规则后再推进。

## 首批实现边界

2026-10-08 偏差承接：下述外部 4096 累计额度是 M3 实际边界，未满足原讨论中 World 依据专门投递契约管理长期去重的目标。负责人明确在 [M4](../../plans/2026-10-08-m4-world投递与去重计划.md) 实现；首批验收不扩大为 World 长时运行保证。

- 内部心跳不占外部去重集合。UserInput/World Event 保留合计 4096 累计精确身份，耗尽后拒绝；没有宣称外部触发无限运行，不通过淘汰 ID 重新允许动作。
- World Event 默认不按 occurredAt 年龄丢弃，也无默认排队期限；来源可声明 expiresAt，过期事实保留接收和终态诊断。UserInput 沿用 120 秒排队期限。
- 心跳是否调用模型或产生动作由 Agent 判断；无动作正常结束并记录。已存在活动或排队心跳时跳过新 tick，跳过只记有限诊断，不合并或补发。
- 统一执行要先明确事实提交与后续可见性；Memory 后续接入也遵守这条边界。首批不实现 Memory，不等于整体架构可以省去该接口位置。

每项新增机制先列输入来源、唯一状态拥有者、外部效果、提交点、取消后保留事实和新代可见内容，再用一个完整纵向场景验证。只在真实外部输入、存储与效果边界校验；内部依赖已成立的类型和调用契约。

## 结构与兼容

同一 Runtime/Session 只有一个受理队列、一个执行 worker。公共 `runtime.triggers.submit` 接收 user_input/world_event，heartbeat 由 Runtime 生成身份并投递同一内核；`runtime.inputs` 保留 M2 方法与返回字段，作为 user_input 适配层。`handleEvent` 提交同一队列并返回该条 RunResult，不再直调模型和工具；失败与取消通过结果表达，受理拒绝抛 InputError。Event 的无动作响应和 Agent 主动结束续轮允许成功，Console 仍要求最终文本。`input-run.ts` 已扩展迁为 `trigger-run.ts`，旧 processEvent/dispatch 循环已移除。

Agent 拥有触发语义和上下文选择。公共记录保留原始 Event、UserInput 或 Heartbeat；不把玩家事件转成 Console 文本。三种来源共享执行期限、请求容量、工具回执与 unknown 停止规则。工具结果只推进当前触发内部的续轮，处理完成后 Runtime 回到等待。

## 身份、顺序和容量

- 去重键为 `(kind, triggerId)`，source 是来源说明；修改 source 不能绕过去重。UserInput 的 triggerId 等于 inputId，World Event 等于 event.id。不同种类允许同名 ID。
- 单线程边界完成验证、占用身份和递增 queueSequence；按受理序号 FIFO，新事件不自动取消活动触发，不按来源插队或合并批次。显式取消/过期可以先完成最终诊断，执行顺序和最终通知顺序不等同。
- 标准容量：待执行 8（不含活动项）、累计外部受理身份 4096、请求 64 KiB、Console 文本 8 KiB、续轮软余量 16 KiB、响应 1 MiB、工具批量/模型轮数各 8；模型轮数还受 Agent.maxTurns 限制。Event JSON 上限 64 KiB。均可在装配时配置。
- Event 的 occurredAt 只表达业务时间，默认无有效期，跨设备时钟偏差不直接判作无效。expiresAt 可显式给出；UserInput 排队最长 120 秒，Heartbeat 默认有效期 5 秒。执行前检查到期；活动处理受执行期限约束。
- 心跳默认关闭，RuntimeOptions.heartbeat 显式启用；默认周期 30 秒，可注入 HeartbeatSource。至多一个未结算心跳，包含过期后仍等待终态追加的项；其间的新 tick 通过 heartbeat_skipped 诊断 heartbeat_pending，队列满诊断 queue_full，不占身份或序号，不自动补发。受理心跳及无动作终态保存，跳过 tick 只保留有限诊断与计数。
- 外部去重身份在同一实例停止/重启后保留，不自动淘汰或重放；内部心跳身份由 Runtime 代次与序号生成。4096 仍是有限外部运行预算，跨进程持续投递和持久去重属于后续批次。

## 投递、记录和生命周期

World 可选同步订阅接口接受异步 sink，返回取消订阅函数。World.start 完成后 Runtime 打开受理并订阅；start 完成表示订阅已装配。订阅前的启动事实由 World 保留，sink 回执拒绝后由 World 决定上游缓冲，不保证 Runtime 自动重投。来源只投递事实，不直接启动 Provider。旧 World 无订阅仍可使用工具接口。

`accepted` 在内存受理后返回，只确认进入内存队列，不等待接收记录追加确认。随受理启动 trigger_received 追加，包含关联、原始事实、受理序号与代次。执行等待该追加完成；写入失败立即关闭受理并停止，后续项不执行。进程退出可能丢失尚未保存的项，本批不承诺重启补投。取消、过期、排队停止同样等待接收追加，然后写最终记录。入模只读取已提交的已完成轮次与当前触发，不把排队事实提前当作当前任务。

执行过程继续及时记录原始事实、run_started、模型请求/响应、工具调用/回执和 run_finished；公开完成在最终记录成功或失败后发出。既有旧 JSONL 可以读取，不自动修补、重放或迁移。新触发记录为追加式 schema 增量。

停止先同步关闭受理、失效 generation 和取消订阅/心跳，再收束 worker、排队终态、所有已进入的存储写入与 World 清理。旧代 sink 返回 stale_generation；迟到模型或工具结果不进入新代。World 已产生但无法确认的效果仍 unknown；即使回执存储失败也停止，无自动重试。

## 验证与边界

无网络验证混合 FIFO、多个 Event 工具串行、上下文连续性、身份隔离/防绕过、背压、心跳跳过/过期、排队取消、停止/重启、迟到 sink/Provider/World、接收与最终写入失败、unknown。阻塞接收追加时，验证 accepted 已返回而执行尚未开始；活动模型或工具期间接收新事件，验证当前处理继续、新事件按 FIFO 等待，且不插队或合并批次。使用真实 JSONL、测试 World 和手动 tick 源，不依赖 Console 排队来证明调度。

本批不交付状态提取/Memory 持久化、恢复/重放、生产 World、跨实例调度、新事件自动取消活动处理、来源优先级或批处理。来源优先级和批处理明确作为后续目标；自动抢占仅保留为候选讨论。真实 Provider 经完整 Runtime 与选定 World 的集成验收仍另记。Console 展示优化由独立计划承担，本批仅适配通用来源诊断。当前结构与验证见 [M3 阶段报告](../../../2026-10-08-M3.0进度与架构图.md)。

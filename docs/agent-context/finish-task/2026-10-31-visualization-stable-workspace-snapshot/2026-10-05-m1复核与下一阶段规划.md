Reproduction: 原有 10 项通过；新增 10 项中 9 项失败。旧 start 的成功/失败会把新代状态覆盖为 stopped；启动取消与并发 stop 会触发三次 cleanup；迟到 read 会恢复 trace；stop 不等待已接收的 append；cleanup 使用已取消的运行信号。工具第二轮缺失原始用户输入、function_call 和 reasoning，并将结果写成 role=tool/tool_call_id。

Repair boundary: start 与 stop 分别持有操作 Promise；旧代启动只结束自己的 Promise，不改变当前状态或重复清理。每次存储 await 后先检查有效性再进入下一步。停止立即阻断新工作，等待停止前已提交的 Session 写入完成后才返回 stopped；已提交写入无法撤销，可在 stopping 期间完成，不进入失效代 trace。存储写入失败由 handling/stop 报错，不以 cleanup deadline 截断写入。World cleanup 使用独立信号，deadline 到达时取消该信号。契约允许模型消息携带工具调用和 Provider 所有的序列化输出项，Agent 从事件/响应/回执恢复消息序列；Responses 将回执映射为 function_call_output 并保留原始输出项。旧 JSONL 字段仍可读取。

Source: OpenAI 官方 Function calling 文档：https://developers.openai.com/api/docs/guides/function-calling 。工具输出使用 function_call_output/call_id；手动管理上下文时回传 response.output，包括工具调用关联的 reasoning 项。

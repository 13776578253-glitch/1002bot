## 审查发现

- P1，src/runtime/input-run.ts:82–84：World 已执行后的一般异常被转换为 failed/world_error，继续模型续轮和待执行队列。World 契约未规定 throw 保证没有副作用；异常本身无法证明外部结果。scratch/m2-review-probe.ts 的 effect_then_throw 场景先通过 FixtureWorld 写入 x=7，再抛出回执异常，结果 first 和 second 均 succeeded，Runtime 仍 running。建议已进入执行且没有明确回执的异常保留原 callId 的 unknown 并收束 Runtime；明确领域失败由 World 返回 failed 回执。
- P1，src/runtime/input-run.ts:90–96：unknown 的 halt 标记和诊断在 tool_outcome 写入之后设置；写入失败时调用已经从 pending 删除，catch 无法再识别它，返回 storage_error/halt=false。探针 unknown_write_failure 场景中 World 返回 unknown，工具回执 append 单独失败，下一条输入仍 succeeded，Runtime 仍 running，且没有 tool_finished 事件。建议在依赖存储的 await 前锁定 unknown 的收束状态，保留 callId 与原因的运行诊断；存储故障不能解除 unknown 对后续执行的阻断。
- P2，src/protocol/input.ts:25–36、src/runtime/input-run.ts:18、95、src/console/terminal.ts:61–69：公共输出没有 Provider 轮次事件/编号；tool_finished 只传状态，不传 ToolOutcome.error，World 提供的 unknown 原因也被丢弃。通用 Console 因而不能按范围要求显示轮次、工具错误和 unknown 原因。离线样例通过最终回复复述工具回执，不能保证其他 Provider 的诊断。建议补充轻量轮次、工具错误代码与原因字段，并验证不暴露 providerData 或凭据。

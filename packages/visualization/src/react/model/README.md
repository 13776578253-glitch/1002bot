# Port candidates and route geometry

P0 contracts are in place without switching the default router: `node-port-allocator.ts` owns physical slots shared by source and target roles, with independent, trunk, packed and spill fallback plus transactional reconcile; `input-fingerprint.ts` hashes inputs and guarded manual paths plus cross-group neighbor tokens, never automatic solutions; `legality.ts` is the single hard gate used by `pathIsClear`; `search-limits.ts` bounds A* expansions and the stitch loop. Reserved paths are indexed, so fixed members are queried per corridor and per segment. Physical slots use `side:index`; logical handles use `side:role:index` and share the same capacity.

P1 adds `route-groups.ts` as an offline solver: star groups are owned by the higher-degree endpoint and sorted by owner id, one shared allocator snapshot coordinates slots across groups, and four modes (`fork`, `trunk`, `mixed`, `lanes`) compete through `ModeEvaluationResult`. Transactional solves reject incomplete modes; non-transactional solves rank by success count. Port allocation is atomic per edge, scores use node-scoped global port keys, locked/frozen routes reserve their stored slot handles and point boxes, each mode gets an independent time slice, and lanes follow target geometry. P1 uses one allocation round; multi-round revalidation stays in P2/P3. `classifyFailure` fixes the retain / incomplete / rollback contract for previous legal paths.

P2 adds joint path-label scoring: `label-candidates.ts` produces several branch-biased candidates per route, a width-4 beam selects one per edge without label overlaps, and `route-quality.ts` scores length, real direction-change bends, crossings, intentional trunk overlap separately from unintended overlap, port crowding, channel stability, label readability and label ownership. Channel order uses target port world projection, not each node's local fraction. Crossing weight is validated by a 10/30/100 px detour matrix: a short detour avoids a crossing, a large one loses. Labels that find no valid slot become `space-exhausted`, and only required labels pay the hidden penalty. Shadow tests compare the old router with the offline solver on six-node, fan, dense-label and L-shaped locked fixtures. The existing candidate router remains the default.

P3 wires the offline solver into the canvas behind `?routing=group`. Physical slot handles are rendered from the same `slotFractions` rule used by `slotAnchor`, so DOM anchors and algorithm coordinates share one source. `route-selection.ts` only accepts a complete `ok: true` group solution; otherwise it returns the same legacy route map, preserving the last legal paths and every existing pinned/locked/frozen contract. The group engine stays active during drag; the legacy cache is the fallback when group routing is ineligible. The renderer hides `space-exhausted` labels until the edge is hovered, keeping a fallback box for reveal, and tags capsules with `data-label-state`. The old router stays available with `?routing=legacy` or no parameter.

`group-route-cache.ts` adds the group-level incremental layer. A group signature covers its edges, endpoint geometry, policy and label text; node movement inside the cached route bounds also dirties it. Dirty groups and groups sharing a node re-solve with one allocator, while unchanged routes stay as fixed reservations and keep object identity. The group engine remains active during drag; release does not force a full solve. A complete group solve skips the legacy retained/cache/apply pipeline and reports zero legacy timing. Visible-route refs update in `useLayoutEffect`; a fallback seeds the legacy cache from the last committed group routes, including a cold cache. Snapshots reuse the same committed node/route render instead of solving again. `routing-status.ts` derives the fallback reason; the canvas renders a notice for protected/frozen/aggregated/incomplete/error states and suppresses the transient dragging/preview cases.

Views may set `portPolicy.direction` to `top-down`; omitted or `auto` uses the relative positions of the endpoints. The overview selects top-down. The router evaluates side-centre port pairs after rejecting card collisions, locked-path intersections and incorrect departures/arrivals. Frozen fragments and boundary ports remain protected by the existing boundary connector.

Feasible candidates expose five costs: Manhattan length, complete-path bends, shared straight-segment length, occupied endpoint sides, and deviations from the preferred source/target sides. Initial comparison is lexicographic: direction, length, bends, portCrowding, overlap. `portPolicy.priority` may reorder those metrics; omitted metrics follow the defaults. Numerical weights and multi-edge rerouting are deferred until larger authored fixtures provide tuning evidence. The existing obstacle-grid search retains its internal bend penalty; port candidates are compared as complete paths.

The simple-path solver compares simple elbows and horizontal/vertical doglegs symmetrically with both port axes included. The obstacle-grid search uses those axes at its first and last step. Rounded SVG corners are applied only after route selection.

The cache scores changed routes against unaffected and already generated routes. It keeps unrelated paths stable and does not revisit the full graph to improve a score. A policy change invalidates automatic path caches once. Path snapshots carry a policy key; older automatic snapshots are recomputed while explicit pinned/locked paths and frozen fragments retain their contracts. Automatic display snapshots are checked against locked obstacles on restore, including when the barrier version is unchanged. Coincident protected fragments of that same frozen edge may be reused; this exception does not cover exterior locked segments.

No feasible candidate produces an empty blocked route. The canvas reports the blocked count, omits the invalid line and excludes it from path snapshots. Node positions, workspace history and locked geometry remain intact.

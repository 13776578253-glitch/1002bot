# Layout intent and route geometry

## Model boundaries

`contracts/` owns serialized view types independently of React Flow. `layout/` owns node geometry, projection and constraints. `routing/` uses layout geometry, and `labels/` uses the resolved paths. `freeze/` composes layout and routing operations. `stages/` combines these results with workspace snapshots before committing a transition. Project and LocalStorage conversions live in `react/persistence/`.

`resolve-routes.ts` is the route entry for the canvas, stage navigation and source revision merge. The caller supplies the engine caches. Current geometry, protection and port policy are shared across search, restored paths and the final result. A complete legal Group result skips Legacy. Otherwise Legacy uses its own incremental cache, and stage callers turn route failures into transition conflicts. Protected paths can share geometry within the same frozen owner. Exterior locks remain obstacles.

`content-intent.ts` owns draft and parent comparison. Explicit layout edits take precedence, with effective positions and sizes used for older or incomplete records. Protected world anchors, frozen frames, canonical path constraints and label pins participate in comparison. Fitted geometry and automatic paths can be saved as recovery data. Confirmation snapshots keep their source revision and literal content.

`label-layout.ts` owns final label placement for both routing engines. Centers lie on the owning segment or capsule edges remain within 2 world units of it. Invalid candidates and detached pins have no placement. Geometry projection restores a valid prior attachment before search; changing to another candidate requires a score improvement of 20. Segment array indices carry no identity. Committed caches use fork/adopt so abandoned React renders do not change attachment history.

`label-snapshots.ts` stamps automatic caches with semantic identity, exact route geometry and policy. Only matching caches seed projection. Node frames, paths and labels are captured after the same React commit, including final parent fitting. Derived cache changes do not affect confirmation, undo comparison or three-way merges. `label-pins.ts` matches authored constraints against visible endpoints, canonical members and their endpoint/port fingerprints; source changes invalidate obsolete pins. Path locks and label pins are independent.


`layout-intent.ts` separates user position and collapsed/expanded size preferences from fitted frames. Position anchors use parent content coordinates (`position + parent.fitOffset - self.fitOffset`). Automatic fitting and measurement do not create user edits. Three-way inheritance compares changed intent, applies chosen anchors, and derives visible container frames afterward. Fixed anchors, frozen ledgers and locked paths are validated against the complete result before commit.

Legacy frames become unknown-origin preferences in working copies; ambiguous changes retain the target draft. Stored confirmations and checkpoints remain literal. Current source revisions preserve historical confirmation content and record its `confirmedRevision`. Session undo restores inheritance metadata along with geometry; refresh persists the chosen draft without saving the undo stack. New checkpoint creation is paused; existing checkpoint arrays are retained and validated when present. `UserGraphOverlay` is persisted for compatibility only and has no active controller or UI caller, so it is recorded as unenabled.

Responsibility details expand inside their existing card without creating children. Nodes with real children expand as structures. Header obstacles and content insets include the responsibility rows. Workspace restoration distinguishes these two shapes; a stage that introduces real children uses its authored container size while keeping the inherited position.

Collapsed cards use 240x80 frames; expanded detail cards use 462x192 frames for up to two responsibilities and 462x280 frames for three or more. The compact 1x2 and paged 2x2 layouts share 210x80 tiles and 8px gaps. Responsibility pages are local UI state and do not change node geometry or route inputs. `responsibilityHeight` includes the reserved grid and pagination area in structural header obstacles. Historical confirmations remain literal; working card frames use the shared dimensions. `normalize-card-layout.ts` fits affected ancestors and resolves unprotected overlaps after size normalization. Static content is chosen explicitly only when architecture recursion is excessive and no internal connections are needed; depth never automatically flattens real nodes.

Authored and automatic drags share edge/centre alignment within six screen pixels. Authored movement applies one displacement to movable selection roots, excludes hidden cards and moving descendants from snap targets, and fits only affected ancestors. During an authored drag, an in-bounds move preserves ancestor frames. On release and content-size changes, frames fit their children while retaining the top-left origin; left/top overflow compensates child coordinates. Explicit user size preferences remain minimum bounds. Automatic unused right/bottom space contracts. Growth ceilings, frozen geometry, protected paths and unrelated components constrain the move; an illegal requested displacement is reduced to its last legal position. Saved geometry and history use the existing drag transaction.

Authored stage additions retain inherited expansion. Hidden additions keep their declared local coordinates. Visible additions search available gaps before finite ancestor growth; expanded frames block their entire area for unrelated additions. Expansion and placement share `fitAuthoredLayout`, which never moves neighbouring components. A card becoming a container uses its declared expanded size as the growth baseline. Conflicts preserve the original state and identify the blocking boundary or component.

Alignment guides span the participating card bounds without exterior extensions. Card and label clipping leaves the visible segments between obstacles.

P0 contracts are in place without switching the default router: `node-port-allocator.ts` owns physical slots shared by source and target roles, with independent, trunk, packed and spill fallback plus transactional reconcile; `input-fingerprint.ts` hashes inputs and guarded manual paths plus cross-group neighbor tokens, never automatic solutions; `legality.ts` is the single hard gate used by `pathIsClear`; `search-limits.ts` bounds A* expansions and the stitch loop. Reserved paths are indexed, so fixed members are queried per corridor and per segment. Physical slots use `side:index`; logical handles use `side:role:index` and share the same capacity.

P1 adds `route-groups.ts` as an offline solver: star groups are owned by the higher-degree endpoint and sorted by owner id, one shared allocator snapshot coordinates slots across groups, and four modes (`fork`, `trunk`, `mixed`, `lanes`) compete through `ModeEvaluationResult`. Transactional solves reject incomplete modes; non-transactional solves rank by success count. Port allocation is atomic per edge, scores use node-scoped global port keys, locked/frozen routes reserve their stored slot handles and point boxes, each mode gets an independent time slice, and lanes follow target geometry. P1 uses one allocation round; multi-round revalidation stays in P2/P3. `classifyFailure` fixes the retain / incomplete / rollback contract for previous legal paths.

`route-quality.ts` ranks path length, direction-change bends, crossings, intentional trunk overlap, unintended overlap, port crowding and channel stability. Label diagnostics do not enter routing scores. Routing returns paths and shared-trunk geometry; `label-layout.ts` places labels after final path restoration.

P3 wires the offline solver into the canvas behind `?routing=group`. Physical slot handles are rendered from the same `slotFractions` rule used by `slotAnchor`, so DOM anchors and algorithm coordinates share one source. `resolve-routes.ts` only accepts a complete `ok: true` group solution; otherwise it returns the same legacy route map, reusing legal paths and applying pinned, locked and frozen constraints. The group engine stays active during drag; the legacy cache is the fallback when group routing is ineligible. The renderer omits invalid labels during hover and focus, and tags visible capsules with `data-label-state`. The old router stays available with `?routing=legacy` or no parameter.

`group-route-cache.ts` adds the group-level incremental layer. A group signature covers its edges, endpoint geometry and policy; node movement inside the cached route bounds also dirties it. Dirty groups and groups sharing a node re-solve with one allocator, while unchanged routes stay as fixed reservations and keep object identity. The group engine remains active during drag; release does not force a full solve. A complete group solve skips the legacy retained/cache/apply pipeline and reports zero legacy timing. Visible-route refs update in `useLayoutEffect`; a fallback seeds the legacy cache from the last committed group routes, including a cold cache. Snapshots reuse the same committed node/route render instead of solving again. `routing-status.ts` derives the fallback reason; the canvas renders a notice for protected/frozen/aggregated/incomplete/error states and suppresses the transient dragging/preview cases.

Views may set `portPolicy.direction` to `top-down`; omitted or `auto` uses the relative positions of the endpoints. The overview selects top-down. The router evaluates side-centre port pairs after rejecting card collisions, locked-path intersections and incorrect departures/arrivals. Frozen fragments and boundary ports remain protected by the existing boundary connector.

Feasible candidates expose five costs: Manhattan length, complete-path bends, shared straight-segment length, occupied endpoint sides, and deviations from the preferred source/target sides. Initial comparison is lexicographic: direction, length, bends, portCrowding, overlap. `portPolicy.priority` may reorder those metrics; omitted metrics follow the defaults. Numerical weights and multi-edge rerouting are deferred until larger authored fixtures provide tuning evidence. The existing obstacle-grid search retains its internal bend penalty; port candidates are compared as complete paths.

The simple-path solver compares simple elbows and horizontal/vertical doglegs symmetrically with both port axes included. The obstacle-grid search uses those axes at its first and last step. Rounded SVG corners are applied only after route selection.

The cache scores changed routes against unaffected and already generated routes. It keeps unrelated paths stable and does not revisit the full graph to improve a score. A policy change invalidates automatic path caches once. Path snapshots carry a policy key; older automatic snapshots are recomputed while explicit pinned/locked paths and frozen fragments retain their contracts. Automatic display snapshots are checked against locked obstacles on restore, including when the barrier version is unchanged. Coincident protected fragments of that same frozen edge may be reused; this exception does not cover exterior locked segments.

No feasible candidate produces an empty blocked route. The canvas reports the blocked count, omits the invalid line and excludes it from path snapshots. Node positions, workspace history and locked geometry remain intact.

Each stage owns overview, structure and full snapshots with independent geometry, paths, frozen ledgers, confirmations and histories. `view-projection.ts` seeds an unvisited projection only. Overview and Full enforce collapsed/expanded projection policies when semantic additions change a node into a container. Stage navigation prepares every mode from its same-name confirmed parent and commits only a complete successful batch. Existing view switching does not synchronize expansion or refit geometry. A rebased draft requires explicit confirmation while previous confirmed content remains available.

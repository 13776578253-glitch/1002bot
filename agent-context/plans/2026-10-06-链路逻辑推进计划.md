# 链路逻辑推进计划

状态：独立工作线已建立。首批输入闭环修复复核、真实 Provider/本地只读工具往返和负责人终端交互确认均已完成；持续世界 Agent 的后续链路继续推进。

## 目标与基线

按 [持续运行方向](../../scratch/Off-topic%20discussion/2026-10-06-M2目标偏差与持续运行方向.md) 和 [持续运行约束](../../scratch/Off-topic%20discussion/持续运行Agent设计约束.md)，推进 World 感知、统一触发调度、Agent/Provider、World 动作和记录/状态的连续运行链路。单次处理结束后返回等待状态。

当前 UserInput 有 FIFO；Event 仍经 Runtime.handleEvent 直接执行，多个 Event 尚未统一串行。World 接口没有感知订阅，心跳没有接入，State 仅注入。真实 Provider 手动结果只证明适配器与本地只读工具往返，不能替代 Runtime/World 的完整链路验收。

责任范围为 src/protocol、src/runtime、src/agent、src/providers、src/state、World 公共契约与 src/runtime/compose.ts。Console 本地编辑与展示由 [Console 计划](2026-10-06-console终端交互计划.md) 负责。

## 下一批：统一触发受理与调度

先形成公共契约与兼容迁移设计，再实现可无界面验证的闭环：

- World Event、Console 可执行输入、Heartbeat 进入同一 Session 的调度边界，保留各自类型、来源与事实语义。
- 明确受理身份、去重、顺序、容量、背压、过期、取消与最终诊断；明确心跳积压的合并或跳过规则。具体数字与策略在设计附件中固定。
- 消除多个 handleEvent 并发执行工具的路径，说明旧入口的兼容或迁移行为。
- 统一生命周期、执行时限、generation 隔离、及时记录和停止写入屏障；unknown 保留诊断并停止，无自动重试或重放。
- 定义 World 事实投递与心跳接入的边界，以测试 World 和可控心跳验证；首个生产 World 仍单独确定。

本批验收覆盖活动输入期间 Event 到达、多个 Event 串行、混合来源顺序与背压、心跳积压及过期、停止/重启、迟到结果、存储失败和 unknown。自动测试不联网，不依赖终端来证明调度正确。

## 后续分批

统一调度后按依赖分别设计：事件记录与投递状态、Session 恢复诊断、Agent 状态接入与持久化、生产 World 感知与动作验收。各批明确记录提交与后续触发可见性，不把 Session 历史或现有 MemoryState 视为完整长期 Memory。

真实 Provider 经完整 Runtime 与选定 World 的集成验收另记结果，与已通过的 Provider 手动验收分开。生产环境、凭据和有外部副作用的场景在实际配置可用时报告人工验收步骤。

## 交付规则

各批交付契约、实现、迁移说明、故障回归、复核和验收记录。先无界面验证，再同步 Console 所需公共字段；Console 的交互优化不作为链路推进的前置条件。摘要/handoff、unknown 恢复/重放、多实例及长期 Memory 产品语义继续延后，除非后续明确变更范围。

# M3 第一批：统一触发设计

状态：架构候选草案，供后续讨论；尚未实现。以下接口、策略与新增参数是 AI 提案，不属于负责人此前冻结的决定。约束基线见 [持续运行约束](../../scratch/Off-topic%20discussion/持续运行Agent设计约束.md) 和 [目标偏差讨论](../../scratch/Off-topic%20discussion/2026-10-06-M2目标偏差与持续运行方向.md)。

## 讨论前需解决的问题

- M2 的 4096 累计受理身份不能直接作为持续触发的长期方案：仅每 30 秒受理一次心跳，约 34 小时就会耗尽，World Event 会进一步缩短预算。下面沿用容量的方案只展示兼容成本；需要设计身份保留范围与心跳身份策略，不能靠自动释放外部事件 ID 引入重复动作。
- Event 有效期应区分事实语义：过时的位置变化与尚未处理的玩家消息不能仅凭同一个年龄阈值丢弃。下文 120 秒是候选机械上限，需要明确来源声明、过期诊断与历史事实保留。
- 心跳是触发源；是否调用模型、是否产生动作由 Agent 判断。跳过积压 tick、合并 tick 和记录无动作结果需要分别定义，不能混为“无需记录”。
- 统一执行要先明确事实提交与后续可见性；Memory 后续接入也遵守这条边界。首批不实现 Memory，不等于整体架构可以省去该接口位置。

每项新增机制先列输入来源、唯一状态拥有者、外部效果、提交点、取消后保留事实和新代可见内容，再用一个完整纵向场景验证。只在真实外部输入、存储与效果边界校验；内部依赖已成立的类型和调用契约。

流式部分输出、工具提前执行、抢占、批处理闸门、跨重启投递水位、上下文 handoff、多协议切换、插件依赖和多消费者路由只在明确场景进入范围后设计。当前非流式、固定装配和单 Session 的边界继续保留。恢复诊断与自动重放分别讨论，unknown 不因心跳或重启自动重试。

## 结构与兼容

同一 Runtime/Session 只有一个受理队列、一个执行 worker。`runtime.triggers` 接收 `user_input / world_event / heartbeat` 判别联合；`runtime.inputs` 保留 M2 方法与返回字段，作为 user_input 适配层。`handleEvent` 改为提交同一队列并等待该条最终结果，不再直调模型和工具；失败结果可读取，受理拒绝抛稳定错误。旧 Event 的无动作响应和 Agent 主动结束续轮允许成功，Console 仍要求最终文本。

Agent 拥有触发语义和上下文选择。公共记录保留原始 Event、UserInput 或 Heartbeat；不把玩家事件转成 Console 文本。三种来源共享执行期限、请求容量、工具回执与 unknown 停止规则。工具结果只推进当前触发内部的续轮，处理完成后 Runtime 回到等待。

## 身份、顺序和容量

- 去重键为 `(kind, triggerId)`，source 是来源说明；修改 source 不能绕过去重。UserInput 的 triggerId 等于 inputId，World Event 等于 event.id。不同种类允许同名 ID。
- 单线程边界完成验证、占用身份和递增 queueSequence；按受理序号 FIFO，不抢占活动触发。取消/过期可以先完成最终诊断，执行顺序和最终通知顺序不等同。
- 沿用标准容量：待执行 8（不含活动项）、累计受理身份 4096、请求 64 KiB、Console 文本 8 KiB、续轮软余量 16 KiB、响应 1 MiB、工具批量/模型轮数各 8。Event 整体 JSON 上限 64 KiB。都是可配置机械边界。
- Event 默认事实有效期为 occurredAt 后 120 秒；未来发生时间拒绝。排队最长 120 秒；可显式给出更早 expiresAt。Heartbeat 默认有效期 5 秒。执行前再检查有效期；已执行的触发不因队列过期中断，执行时限另算。
- 心跳默认周期 30 秒，装配时显式启用。至多一个活动或排队心跳；其间的新 tick 返回 skipped/heartbeat_pending，队列满返回 skipped/queue_full，不占身份或序号，不自动重投。跳过有实时/有限缓存诊断，不写无动作的逐 tick 历史。受理心跳与其他来源按 FIFO 排队。
- 候选兼容方式：去重身份在同一实例停止/重启后保留，不自动淘汰或重放。4096 只能表达有限运行预算，不能据此宣称已解决持续运行身份管理；该部分待讨论调整。跨进程持续投递/去重持久化属于后续批次，不能用缓存淘汰暗中重新允许动作。

## 投递、记录和生命周期

World 可选同步订阅接口接受异步 sink，返回取消订阅函数。World.start 完成后 Runtime 打开受理并订阅；start 完成表示订阅已装配。订阅前的启动事实由 World 保留，sink 回执拒绝后由 World 决定上游缓冲，不保证 Runtime 自动重投。来源只投递事实，不直接启动 Provider。旧 World 无订阅仍可使用工具接口。

受理只确认内存队列；随受理启动 trigger_received 追加，包含关联、原始事实、受理序号与代次。执行等待该追加完成；写入失败立即关闭受理并停止，后续项不执行。取消、过期、排队停止同样等待接收追加，然后写最终记录。入模只读取已提交的已完成轮次与当前触发，不把排队事实提前当作当前任务。

执行过程继续及时记录原始事实、run_started、模型请求/响应、工具调用/回执和 run_finished；公开完成在最终记录成功或失败后发出。既有旧 JSONL 可以读取，不自动修补、重放或迁移。新触发记录为追加式 schema 增量。

停止先同步关闭受理、失效 generation 和取消订阅/心跳，再收束 worker、排队终态、所有已进入的存储写入与 World 清理。旧代 sink 返回 stale_generation；迟到模型或工具结果不进入新代。World 已产生但无法确认的效果仍 unknown；即使回执存储失败也停止，无自动重试。

## 验证与边界

无网络验证混合 FIFO、多个 Event 工具串行、上下文连续性、身份隔离/防绕过、背压、心跳跳过/过期、排队取消、停止/重启、迟到 sink/Provider/World、接收与最终写入失败、unknown。使用真实 JSONL、测试 World 和手动 tick 源，不依赖 Console 排队来证明调度。

本批不交付状态提取/Memory 持久化、恢复/重放、生产 World、跨实例调度或优先级策略。真实 Provider 经完整 Runtime 与选定 World 的集成验收仍另记。Console 展示优化由独立计划承担；本批提供兼容字段和通用来源诊断。
